# Manager Board v2.14.1 — Routed Workfront Request Backlog

This patch restores backlog visibility for Workfront requests that are moved into a different hosting project by queue routing.

- **Routed requests:** when a request topic is configured, Manager Board verifies that it belongs to the selected queue and retrieves requests by that exact topic, including routed requests. Connections without a topic retain the existing queue-project scope.
- **Sync details:** the Request Backlog now offers a collapsed explanation of the source, retrieved requests, routed requests and exclusions for closed or converted items. Empty-state guidance distinguishes setup, refresh errors and view filters.
- **Offline continuity:** a failed refresh preserves the saved backlog and its diagnostics.

After updating, run **Sync Workfront**, then open **Projects → Request Backlog**. If the expected requests are still missing, expand **Sync details**. Workfront permissions and your configured queue/topic still determine access; Manager Board does not perform a tenant-wide search or change request routing.

Existing project creation and template conversion, imports, reviewed publishing and rollback, saved sorting and column widths, exports, themes, licensing and Workspace/Vault continuity are preserved. Schema 48 is unchanged. Local AI models remain optional separate files.
