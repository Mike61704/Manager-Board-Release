# Manager Board v2.15.0 — Workfront Request Conversion and Project Recovery

- **Convert an existing request:** in Projects → Request Backlog, choose Convert to Project beside Open in Workfront. Review the configured template and project name, then type CONVERT. The original request and custom forms are preserved, template tasks/sharing are inherited, and the project manager remains unassigned. No new request is submitted and staged Manager Board tasks stay unpublished.
- **Connect & Sync from Projects:** reconnect from Projects, task views and publish/conversion reviews using your saved connection. After sign-in, the normal sync/import confirmation runs. The action does not publish changes automatically or extend the provider's session lifetime.
- **Clearer request forms:** compact controls align in even rows, narrative fields span full rows, and required fields use a subtle red border/tint plus an accessible Required label.
- **Publication recovery:** recheck remaining changes after a failure. Newly converted projects allow bounded read-back verification before selected tasks proceed; authentication and permission errors still stop publication. Saved identities protect retries from duplicate requests/projects.

After conversion, run Sync Workfront to refresh the project and inherited template tasks. Approvals, permissions and configured queue/topic scope remain enforced. Actual template access, report visibility and first-publish behavior should be verified in your connected environment.

Existing imports, reviewed publishing/rollback, task hierarchy, saved sorting and column widths, exports, themes, licenses and Workspace/Vault continuity are preserved. Schema 48 is unchanged. Local AI models remain optional separate files.
