# Manager Board v2.18.0 — Workfront Project Shelving

- **Shelved Projects:** defer an existing Workfront project through a reviewed Shelve Project action, with an optional reason and a dedicated view for returning to it later.
- **Backlog planning pointer:** the original project is placed On Hold (or your configured dormant status) while a lightweight request represents it in the configured backlog queue/topic. Its tasks remain on the original project.
- **Reactivate the same project:** restore the exact saved prior status, close the planning request, and retain the original project/task IDs, assignments, dates, comments/history and Manager Board mappings. A manually deleted pointer does not prevent reactivation.
- **Recovery and continuity:** validated restore points, complete local task checks, durable operation receipts, sync protection and explicit interrupted-operation recovery protect deferred work. Missing originals stop for recovery rather than silently creating duplicates. Shelving pointers cannot be converted to new projects through Manager Board.
- **Configurable statuses:** Connections exposes dormant project and placeholder closed status codes; shelving uses the existing adjustable request queue and optional topic. Edits made while shelved remain queued for publication after reactivation.

Schema 48 is unchanged. Existing onboarding, exports, team filters, themes, saved sorting and widths, licensing, backups and Vault workflows remain supported. Local AI models remain optional separate files.

After updating, check the queue/topic and status codes in Settings > Connections, sync the full project, then review Shelve Project from its controls. Use Reactivate Project from Shelved Projects or the backlog pointer. Automated Workfront verification uses synthetic responses; live tenant acceptance remains pending and depends on your permissions, required request fields and approval rules.
