# Manager Board v2.0.66 — Workfront People Provisioning

Manager Board can now turn a verified Workfront direct-report roster into a careful, review-first People update—without surrendering local control. 👥✨

## What’s new

- Adds **Import People from Workfront** to the People page.
- Uses the last verified Workfront roster and identifies the configured manager’s direct reports in the configured Home Team.
- Matches existing People by stable Workfront User ID, then unique email, then unique normalized name or alias.
- Collects Workfront name, title, email, Home Team, Home Group, manager, and active status for review.
- Lets the manager select or deselect each person before anything changes.
- Defaults blank Manager Board values to **Apply Workfront** and existing local values to **Keep Manager Board**.
- Offers explicit **Keep Manager Board**, **Apply Workfront**, and durable **Ignore** choices per field.
- Hides the configured manager from the import review and rejects that identity at the application boundary.

## Safety and continuity

- Workfront remains read-only for this workflow.
- A preview is required before every apply.
- Apply creates a validated restore point, rejects stale previews, and commits selected People changes transactionally.
- Reopening an already reconciled roster produces a clean up-to-date result instead of repeating no-op changes.
- No People record is deleted or deactivated automatically.
- Manager-owned People fields remain under Manager Board control.
- Project synchronization, project pruning, reporting, publishing, intake, Local AI, licensing, updates, backups, restore, and schema v41 remain unchanged.
- The complete CPU, Vulkan, OpenVINO Intel NPU, and TBB runtime remains included.
- Offline device-bound activation remains valid across normal updates on the same Windows profile.
- No source code, private signing material, organization data, user data, or GGUF model is included.
