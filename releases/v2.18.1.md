# Manager Board v2.18.1 — Shelving Planning Context and Progress

- **Planning context on backlog placeholders:** carry Anticipated Year, Quarter, Proposed Recommendation, priority, Business Need and other supported matching form values from the original Workfront project. Review copied values and complete missing details before confirming Shelve Project.
- **Clear on-hold indicator:** keep the original request name and include an explicit notice that the existing project is on hold and the placeholder must not be promoted. The request includes business need and a link to the original project.
- **Visible Workfront progress:** see the current activity and progress while shelving, reactivating or recovering an interrupted operation. The dialog stays open at confirmed completion and shows stopped operations with recovery information when needed.
- **Preserved recovery and identity:** copied values are verified before saving the local Shelved transition. Existing restore points, compensation, original project/task IDs, assignments, history and mappings remain intact. Reactivation preserves manually edited placeholder fields; existing placeholders are not automatically rewritten.

Schema 48 is unchanged. Planning fields use the custom form configured for your backlog queue/topic and your Workfront permissions. Missing required values stop before changes. Optional Local AI models remain separate files.

After updating, review the copied planning values in Shelve Project, confirm, and watch the progress display. The original Workfront project remains authoritative for tasks. Live Workfront behavior should be verified in your connected environment.
